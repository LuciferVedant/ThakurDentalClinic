# Thakur Dental Clinic - Management System

A comprehensive full-stack dental clinic management system with role-based access control, Google OAuth integration, real-time queue management, pre-arrival reminders, clinical scribing, and a modern responsive dashboard.

## Tech Stack

### Frontend
- **React 18** with TypeScript
- **Redux Toolkit** for state management
- **Vite** for build tooling
- **React Router** for client-side navigation
- **TailwindCSS** for UI layout and styling
- **Google OAuth 2.0** for patient authentication
- **Axios** for API requests

### Backend
- **Go 1.21+**
- **Gin** web framework
- **GORM** ORM
- **PostgreSQL 15+** database
- **JWT** for session authentication
- **Server-Sent Events (SSE)** for real-time notifications
- **Google OAuth 2.0** verification

## Key Features

### 1. Unified Authentication
- **Patients**: Google OAuth sign-in/sign-up or manual credentials using either **Email Address, Phone Number, or both**. At least one contact method is required.
- **Staff (Doctors & Receptionists)**: Secure credentials generated by Admin Doctors, requiring **both Email Address and Phone Number** to register.
- **JWT Protection**: Session tokens are passed securely to authenticate requests under a unified role-based access control (RBAC) middleware.
- **Form Validations**: LoginPage and signup forms implement inline error messages and visual indicators for invalid fields, along with interactive info tags explaining the optional email/phone logic.
- **Password Recovery**: Secure, single-use password recovery workflow via registered Email and/or Phone Number, using cryptographically random tokens (expires in 15 mins) and enforcing strict replay protection.

### 2. Intelligent Queue Tokening
- **Sequential Tokening**: Booking an appointment issues a daily sequence token (`#1`, `#2`, etc.) and calculates an initial `EstimatedStartTime` based on a standard 35-minute slot increment.
- **Daily Booking Restriction**: Restricts patients to one appointment per day.

### 3. Dynamic Queue Shifting & Live Notifications
- **Overrun Propagation**: If a consultation exceeds its 35-minute duration, the backend automatically recalculates and shifts subsequent patient estimated start times for that doctor.
- **Real-Time Client Alerts**: Active patient dashboards receive instant SSE notifications (e.g. `QUEUE_SHIFT`, `DOCTOR_REASSIGNED`, `PRE_ARRIVAL_REMINDER`) triggering reactive UI updates without manual reloads.
- **Timing Shifts Acceptance**: Shifts flag the appointment as unaccepted. Patients review the delay alert banner on their dashboard and click **"Accept Shift"** to confirm.

### 4. Staff & Receptionist Overrides
- **Manual Delay Adjustments**: Receptionists/Doctors can manually add `+15m` or `+30m` delays directly on patient queue cards, propagating shifts down the day's line.
- **Pre-Arrival Call List**: A dedicated checklist for receptionists showing upcoming patients (starting within 45 minutes). Receptionists can log courtesy arrival reminder calls with a single click.
- **Admin Doctor Reassignment**: Admin Doctors can dynamically reassign consulting doctors on scheduled or arrived appointment cards using a dropdown.

### 5. Clinical Checkout & Payment Receipts
- **Scribing Modalities**: Doctors can complete visits by uploading manual prescription scans (photos) or typing digital diagnosis notes.
- **Payment Bookkeeping**: Staff selects the checkout payment method (**Cash** vs **Online (UPI/Card)**) inside the completion modal.
- **Invoice receipt Generation**: Upon completion, the database updates the appointment status to `completed` and the payment status to `paid`. 
- **Printable Receipts**: The patient views their records history containing a formatted **Invoice & Receipt Summary** (reference ID, ₹500 fee, payment status/mode, transaction timestamp) and can click **"Print Receipt"** to trigger a PDF/printout.

## Setup Instructions

### 1. Google OAuth Setup
1. Go to [Google Cloud Console](https://console.cloud.google.com/)
2. Create or select a project.
3. Enable the Google+ API.
4. Create OAuth 2.0 Client Credentials.
5. Add the authorized redirect URI:
   - `http://localhost:5173/auth/google/callback` (for frontend callback)
6. Copy the Client ID and Client Secret.

### 2. Database Setup
Ensure PostgreSQL is running.

#### Using Docker (Recommended)
```bash
# Start PostgreSQL container
docker-compose up -d

# Verify container status
docker ps
```

#### Local PostgreSQL Installation
```sql
CREATE DATABASE thakur_dental_clinic;
```

### 3. Backend Setup
```bash
cd backend
cp .env.example .env
# Configure JWT_SECRET, Google Client IDs, Database URL, and SMTP parameters (SMTP_HOST, SMTP_PORT, SMTP_USERNAME, SMTP_PASSWORD, SMTP_FROM) in .env for password recovery emails. SMS notifications are printed to the console output in development and testing.

# Install Go modules
go mod tidy

# Run migrations and seed database
go run cmd/server/main.go
```
The backend server starts on `http://localhost:8080`.

### 4. Frontend Setup
```bash
cd frontend
npm install
cp .env.example .env
# Configure VITE_GOOGLE_CLIENT_ID and VITE_API_URL in .env

# Start dev server
npm run dev
```
The frontend application starts on `http://localhost:5173`.

## Key API Endpoints

### Public Endpoints
- `GET /health` - Health check status
- `POST /api/auth/login` - Email/password staff/patient login
- `GET /api/auth/google/url` - Fetch Google auth URL
- `GET /api/auth/google/callback` - OAuth callback exchange
- `POST /api/auth/forgot-password` - Request password recovery link
- `POST /api/auth/verify-reset-token` - Validate recovery token status
- `POST /api/auth/reset-password` - Update password and invalidate token

### Protected Endpoints (Auth Required)
- `GET /api/auth/me` - Get current session info
- `POST /api/auth/logout` - Invalidate session token
- `GET /api/auth/stream` - Establish real-time SSE listener connection
- `GET /api/appointments` - List active user appointments
- `POST /api/appointments` - Schedule a new appointment token

### Staff-Only Endpoints (Doctor/Receptionist)
- `PUT /api/appointments/:id/arrived` - Mark patient check-in
- `PUT /api/appointments/:id/start` - Start consultation (`actualStartTime` recorded)
- `PUT /api/appointments/:id/complete` - Complete visit, write prescription, log payment method
- `PUT /api/appointments/:id/delay` - Manually postpone estimated start time

### Patient-Only Endpoints
- `PUT /api/appointments/:id/accept-shift` - Acknowledge queue timing shifts

### Admin-Only Endpoints
- `POST /api/users/staff` - Add doctor or receptionist accounts
- `PUT /api/users/:id` - Update user properties (e.g. toggle staff activation status, change specialization)
- `PUT /api/appointments/:id/reassign` - Reassign scheduled/arrived doctor
